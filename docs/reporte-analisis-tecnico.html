1. Resumen ejecutivo

El proyecto consiste en desarrollar un addon para Strimio, la aplicación de escritorio multi-servicio para escuchar música (Spotify, YouTube Music, Tidal, Deezer, etc.) construida sobre Electron + React + Redux. Este documento cubre la Fase 0 (Análisis): estudio del ecosistema y stack de Strimio, clasificación de los tipos de extensiones soportadas, selección del addon a construir, definición de requisitos, criterios de aceptación, lenguaje de implementación y una estimación preliminar que servirá de insumo directo para el roadmap (documento siguiente del proyecto).

Decisión principal: se implementará un Addon de tipo "Provider/Plugin" llamado provisionalmente strimio-swal-provider (SweetAlert Provider Bridge): un módulo instalable desde el mercado de addons de Strimio que aporta capacidades de notificación/modal interactivos mediante SweetAlert2 y un conector de proveedor de música de ejemplo, siguiendo exactamente las convenciones de manifiesto y API pública de los addons de Strimio (manifest.json, main.js, API pluginManager/alertManager).
  • Lenguaje: TypeScript (compilado a JavaScript ES2020 CommonJS), por alineación con el núcleo del proyecto y tipado de la API del host.
  • Entrega esperada del roadmap: 5 fases / ~14 sprints de 1 semana (~14 semanas), con hitos de MVP en la fase 3.
  • Riesgo principal mitigado: dependencia de APIs internas no documentadas del host → se define una capa host-api aislada y versionada.

3. ¿Qué es Strimio y cómo funciona su sistema de addons?

Strimio es un reproductor de música de escritorio multiplataforma (Windows/macOS/Linux) que agrega varios servicios de streaming en una sola interfaz. Está construido con Electron (contenedor de escritorio), React (UI), Redux Toolkit (estado global) y webpack (empaquetado). Su diferenciador frente a otros clientes es la extensibilidad: un Plugin/Add-on Manager integrado con un mercado desde el cual el usuario instala extensiones sin recompilar la aplicación.

3.1 Ciclo de vida de un addon en Strimio

[Usuario] → Market de Addons → descarga paquete (.zip/npm)
   → Validación de manifest.json (id, version, apiVersion, permissions)
   → Registro en PluginManager → carga de main.js en sandbox/contexto del host
   → onInit(ctx) → suscripción a hooks/eventos → ejecución → onDeactivate() → unregister()

3.2 Contrato mínimo de un addon (convención Strimio)

{
  "manifest.json": {
    "id": "com.ejemplo.swal-provider",
    "name": "SweetAlert Provider Bridge",
    "version": "1.0.0",
    "apiVersion": "^1.0",          // compatibilidad con el host
    "type": "provider",            // provider | ui | tool
    "main": "dist/main.js",
    "author": "...", "description": "...",
    "permissions": ["notifications", "player.read", "ui.alerts"],
    "icon": "assets/icon.png",
    "engines": { "strimio": ">=3.0.0" }
  },
  "main.js":  // punto de entrada exportando: init(ctx), destroy(), settings?
}
Puntos de extensión observados en el host: registro de proveedores de música (catálogo, búsqueda, playback, cola), hooks de reproductor (play/pause/skip/trackChange), alertManager/notificaciones nativas, temas e inyección de CSS/paneles UI, atajos de teclado y comandos.

6. Addon elegido: «SweetAlert Provider Bridge» (tipo A+C híbrido)

Nombre provisional: strimio-swal-provider · ID: com.ejemplo.swal-provider · Tipo declarado en manifest: provider (con sub-módulo tool de alertas).

Descripción: addon instalable desde el market de Strimio que:
  1. Módulo de alertas (tool): integra SweetAlert2 como capa de notificación/modal del addon y la expone a otros contextos del host mediante el canal de eventos (swal.notify, swal.confirm): confirmaciones de cola, avisos de error de playback, "now playing" elegante, prompts de búsqueda.
  2. Módulo proveedor (provider): registra un proveedor de demostración/extensión ante el pluginManager de Strimio que consume una API pública de música (p. ej. Jamendo/Internet Archive — catálogo libre, sin credenciales privadas) y lo inyecta en la barra lateral con búsqueda, portadas y reproducción, usando las alertas SweetAlert para estados vacíos, errores y confirmaciones.
  3. Configuración persistente: panel de opciones del addon (tema de alertas, volumen, frecuencia de "now playing") guardado en el almacenamiento de addons del host.

  • Cubre los dos contratos más importantes del sistema de addons (registro de provider + alertas/eventos), lo que hace el trabajo útil como plantilla para futuros addons del proyecto.
  • SweetAlert2 es estándar de facto para modales, MIT, sin dependencias: reduce riesgo y tamaño.
  • El provider de ejemplo usa APIs libres (Jamendo/IA): evita claves privadas y problemas legales.
  • Escalable: puede degradarse a MVP (solo alertas) si el provider bloquea, sin cancelar el proyecto.

8. Lenguaje de programación

Elegido: TypeScript
  • El núcleo de Strimio usa JS/TS moderno; tipamos el ctx del host y detectamos roturas de API al compilar.
  • Mejor refactorización y documentación viva (interfaces = contrato con el host).
  • Compila a JavaScript ES2020 CommonJS → ejecutable directamente por el loader del PluginManager (que espera JS plano).
  • Ecosistema de tests (ts-jest) y lint maduro.
Alternativas descartadas
  • JavaScript llano: cero fricción de build pero sin garantías de tipos sobre una API de host cambiante → riesgo alto de regresión silenciosa.
  • React dentro del addon: duplica runtime y choca con el árbol del host; se prefiere DOM imperativo ligero + SweetAlert2.
  • Svelte/Preact: innecesarios para el alcance; añaden build complejo.

Convenciones: ESM en fuente → bundle CJS con esbuild; strict: true, ESLint recommended + prettier; commits convencionales (feat|fix|chore(scope): …); semver para el addon y política apiVersion compatible con el host.

12. Criterios de aceptación (CA)

Formato Dado/Cuando/Entonces (Gherkin resumido). Cada CA es automatizable o verificable en demo.

Historia H1 — Instalación y carga

  • CA-1.1: Dado Strimio en ejecución, cuando instalo el addon desde el market y lo activo, entonces aparece en "Mis addons" con estado Activo sin reiniciar.
  • CA-1.2: Dado un manifest con apiVersion incompatible, cuando intento activarlo, entonces Strimio muestra advertencia y el addon queda Bloqueado (no crashea).
  • CA-1.3: Cuando desactivo el addon, entonces desaparece su panel lateral y ningún evento suyo vuelve a emitirse (verificado por spy de listeners).

Historia H2 — Alertas SweetAlert

  • CA-2.1: Dado el addon activo, cuando ocurre un error de playback del host, entonces se muestra una swal de error con mensaje legible y botón "Reintentar" que reintenta la operación.
  • CA-2.2: Cuando invoco confirm(), entonces el resultado true/false se propaga al llamador y el modal cierra con Esc/click-fuera según configuración.
  • CA-2.3: Dado tema oscuro activo en Strimio, cuando se muestra cualquier alerta, entonces sus colores corresponden al tema (snapshot visual).
  • CA-2.4: Cuando 5 eventos de toast llegan en 1 s, entonces se muestran máximo 3 apilados y el resto en cola FIFO.

Historia H3 — Provider de música

  • CA-3.1: Dado el panel del provider abierto, cuando busco "lofi", entonces en < 2 s veo ≥ 1 resultado con título, artista y portada.
  • CA-3.2: Cuando pulso ▶ en una pista, entonces Strimio la reproduce (estado playing en el player del host) y aparece metadato correcto.
  • CA-3.3: Dado modo offline, cuando busco, entonces veo swal informativa "sin conexión" con opción de reintentar y la última caché sigue navegable.
  • CA-3.4: Cuando pagino, entonces se solicitan exactamente los siguientes 20 ítems sin duplicados.

Historia H4 — Configuración

  • CA-4.1: Cuando cambio "toasts now-playing" a OFF y recargo Strimio, entonces el ajuste persiste.
  • CA-4.2: Cuando restauro valores por defecto, entonces el addon vuelve a comportamiento inicial sin reinstalar.

Definition of Done (transversal)

  • PR con descripción, tests nuevos que fallan sin el feature, CI verde (lint+unit+integration+build).
  • Cobertura ≥ 80 % en módulos tocados; documentación de API interna actualizada.
  • Paquete .zip reproducible generado por pipeline con checksum.
  • Sin regresión en suite E2E de humo (instalar→buscar→reproducir→desinstalar).
